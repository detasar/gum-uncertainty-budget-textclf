**T5 closed API LLMs (exploratory; added 2026-10-17 after the preregistration, see deviation 11).** Scored over the network on 2026-10-17 between 17:09 and about 18:00 Istanbul time (UTC+3). Closed API models can change without notice behind the same name, so these cells describe the models as served on that date. Model ids: `gpt-6-luna` through the OpenAI Decisions API (`POST /v1/decisions`). The response carries only the name `gpt-6-luna`, with no dated snapshot. `gpt-4.1-nano` through `/v1/chat/completions`. The response reports `gpt-4.1-nano-2025-04-14`, with several `system_fingerprint` values (listed in `results/api/api_tables.md`, Table A6). Both see the same prompt prefix as the T3 LLMs: "Read the following {genre} and state its {facet}.\n\nText: {text}".
- *gpt-6-luna (Decisions).* Each wording set is one `choice` question ("What is the {facet} of this {genre}? Choose the best option."). Its choices are the K label strings of that set. The API returns a probability for every choice. These probabilities are **quantised to 0.01**: in the pilot, 100% of 61,960 values lie on the 0.01 grid, there are 101 distinct values, 62.5% are exactly 0 and 17.3% exactly 1. We floor them at ε = 1e-4 and renormalise (`core.API_EPS`) so that scores and logs stay finite. A small share of answers come back as `refusal` with no probabilities, mostly for invalid ALL/homogeneous wordings. These are stored as missing and replaced by the uniform distribution in the analysis, and their counts are in Table A1. Several questions (one per wording set) go into one request (60 per request for the main runs, 31 for the order/retest runs). The pilot showed that this changes nothing (§3.10).
- *gpt-4.1-nano (chat logprobs).* One request per item × wording set: `max_tokens` 1, `temperature` 0, `seed` 0, `logprobs` true, `top_logprobs` 20. The options are listed as letters A, B, C, … (K up to 18) and the model is asked to "Answer with the letter of the option only." The class score is the first-token log-probability of the option's letter (log-sum-exp over the `X` and ` X` tokens), and the class probabilities are the softmax over the K letters. **A letter missing from the top-20 list** gets the smallest top-20 log-probability returned. That value is an upper bound on its true log-probability, so missing options are treated as "at most as likely as the 20th token". The share of letters that are missing is reported per cell (Table A1). With K = 14 or 18 options, many options can never appear in a top-20 list that also holds the formatting variants of the winning letter.
- *Which models.* The Decisions API offered only gpt-6-luna; gpt-4.1-nano, gpt-5.4-nano and gpt-5.6-luna are not available there. Among chat models with logprobs, gpt-4.1-nano and gpt-4o-mini both worked; gpt-5-nano refuses logprobs. gpt-4.1-nano was chosen as the cheapest, at $0.10 per 1M input tokens and $0.40 per 1M output tokens.
- *Wording sets and items.* Same items as T1/T3: the first 1,200 pool items (DBpedia: 1,000). The sets are official + 30 VALID + surface + identity + nonsense + shuffled. gpt-6-luna on AG News and BBC also scored the STRICT, ALL and homogeneous sets, so H3c is available for those two cells only. No single-class-replacement sets were scored, so dose-response (H3b) is **not measured for T5**; the SST-2 value that `aggregate.py` reports comes from a few incidental matches and is not interpreted.
- *Storage.* T5 class probabilities depend on the whole option list, not on each label string alone. They are therefore stored per wording set (`P`: items × sets × K), not per string as in `score_llm.py`. `core.Scorer` gained a small `api` branch; `analyze.py` is unchanged. Every request and its usage are cached in `raw/api_cache/<model>/<ds>__<cond>.jsonl`, and the scorer can resume from that cache. `src/api_build.py` assembles the npz files.
- *Option order (exploratory new factor).* On AG News and BBC, the first 600 items × official + 30 VALID sets were rescored in two random option orders per set (fixed per dataset, set and order, the same for every item). The canonical class order is the third order. For gpt-4.1-nano a change of order also changes which letter each label gets. Order levels are nested in wording. Mean set size (n = 250, α = 0.10, 200 splits) is decomposed as wording + order(wording) + split + wording×split + residual by method of moments, with a two-way bootstrap CI (`src/api_order.py`).
- *API test-retest.* AG News items 0–199 × official + 30 VALID sets, scored three times: in the main run and in two later reruns on the same day.
